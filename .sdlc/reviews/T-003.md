### Nits (non-blocking)

1. `src/vramsherpa/main.py:1133`: Starlette's `RedirectResponse` runs the URL through `quote(..., safe=":/%#?=@[]!$&'()*+,;")`. Characters that browsers leave raw in a hand-typed query but that are not in that set (`|`, `^`, `{`, `}`, backtick) come out percent-encoded, for example `?a=|` gives `Location: /results?a=%7C`. The meaning is the same, and links pushed by htmx (built with `encodeURIComponent`) never contain these raw, so the R-081 example and every real old link pass through unchanged. It is still not strictly "byte for byte". A raw non-ASCII byte in the query would also be re-encoded through latin-1, but browsers always percent-encode those. If strict passthrough is ever wanted, the fix is to set `Location` on a plain `Response(status_code=302, headers={"Location": ...})`, as the task notes allow, and add a raw-`|` case to `test_old_partial_link_keeps_percent_encoding_in_location`.
2. `tests/test_history.py`, `test_old_partial_link_location_is_a_path_whatever_the_host_or_scheme`: the TestClient does not apply proxy headers, so `X-Forwarded-Proto` and `X-Forwarded-Host` have no effect here. The test still proves the `Location` ignores the request's scheme and host (the URL is `https://localhost`). Its name slightly overstates what it covers.
