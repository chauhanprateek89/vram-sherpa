### Stage 2: code quality

- **Correctness.** The script guards `document.currentScript` being null and checks `data-open-wide` before it sets `open`, so it fails safe. It runs during parsing, before first paint, so wide screens do not see it flash closed. An in-place refresh re-renders the disclosure closed on a phone, so a tile a visitor opened there closes again. ADR-0006 point 2 accepts this, and it matches how the shell re-renders.
- **Security (rule 11).** No new route, parameter or stored input. The inline script interpolates no data. Model names, titles and descriptions are autoescaped by Jinja, and `hardware_query_string` is unchanged from before. ADR-0006 already records that the inline script must survive if a Content-Security-Policy is ever added. No deeper security review was needed for a template, CSS and copy change.
- **Constitution.** Rule 9 (Cache-Control) is untouched. Rule 16 is not affected, because picks show no verdict. Rule 19 holds. Rule 21 holds (`ASSET_VERSION` bumped). Rule 10 is covered by the comparison above, and QA still owes its own pass.
- **Tests.** They test behaviour from the rendered HTML: element order, closed state, that the script follows the `</details>` directly, the media query, the copy, link targets and the hidden case. They would fail without the change. The CSS test checks the removed selectors are gone and that the one `whyIn` keyframes is reused.
- **Fit.** The include follows ADR-0006 point 1, and the CSS follows the mockup line for line in the file's newer single-line style.

### Nits

1. `src/vramsherpa/static/css/styles.css:248`: the legacy `body { line-height: 1.45 }`, which predates this task, makes `.pick-title` and `.pick-meta` 1 px shorter than the mockup's 1.5. It is not T-014's rule, but the tiles show it. Fixed would be the base line-height matching `tokens.css` and the mockup, in whichever task owns the base styles, or left for QA to judge.
2. `styles.css:1038-1042`: the `.picks > summary` list-style, marker, `::after` chevron, `[open]` rotation and hover rules repeat the `.filters > summary` rules from T-012 word for word. The mockup groups them (`.filters > summary::after, .picks > summary::after`). Fixed would be one grouped rule.
3. `tests/test_ui_markup.py`, `test_top_picks_tiles_carry_the_new_descriptions_and_no_ranking_words`: the source check looks only for `ranked` (not `ranking`) and slices `main.py` between `def _top_picks` and `def _example_chips`, so it depends on that function order. The rendered-text check already covers both words, so the source check could go or use a regex on the description strings.
4. No test pins which variants R-024 picks for a known query (for example the three models above for the reference query). The selection code is unchanged here, so this is an old gap, but one assertion on the three model names would protect R-024 and R-078's "same models" rule through the rest of the overhaul.
