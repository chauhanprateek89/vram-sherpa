**Quality issues (non-blocking):**

- **Q-1.** `src/vramsherpa/templates/results_list.html:99` with `base.html:49` (`#i-info`). The unseeded info icon's "i" is drawn in `var(--pill-bg, #fff)`, and nothing sets `--pill-bg` on the empty sheet, so the glyph is always `#fff`.
  - In dark, the disc is `--ink` `#F3F1FF`, so the glyph measures 1.11:1 against it. The icon renders as a plain pale disc with no visible "i".
  - Light is fine (18.3:1).
  - The approved mockup and the `unseeded-*-dark.png` renders have the same defect, so the build matches rule 10.
  - R-077's 3:1 list (field borders, button outlines, gauge, reserve band, classification markers) does not name this icon. It is also `aria-hidden` next to text that says the same thing. So I am not failing the task on it.
  - Fixed would be one line, for example `.empty-status { --pill-bg: var(--panel-solid); }`, the same pattern `.notice` and `.counts li` already use. That gives a dark "i" on the pale disc in dark mode and leaves light mode unchanged. Because it departs from the approved render by the glyph colour only, the orchestrator or QA should decide whether it lands here, in T-020, or as a design note.
