### Stage 2: code quality

Correctness:

- The `text/html` check is case-insensitive and also matches `text/html; charset=utf-8`.
- If a response has no `content-type` (a 304, for example), the middleware passes it through unchanged.
- `Vary` handling is correct. It merges several `Vary` header lines into one, ignores empty items, removes duplicates case-insensitively and keeps the original order.
- Order: Starlette makes the last `app.middleware` registration the outermost, so `host_guard` runs first, as the comment says.
- Any HTML error responses would also get `no-cache`. That is harmless and matches ADR-0004 ("any response whose Content-Type starts with text/html").

Constitution, by rule:

- Rule 8: host guard logic unchanged. The unknown Host still gets 400 JSON, and a test covers it.
- Rule 9: satisfied. This is the purpose of the task.
- Rule 11: no production routes added. The `/test-only/*` routes exist only on app instances built inside tests.
- Rule 18: no CI check removed or weakened.
- Rule 19: SQLite temp DB, no network.
- Rule 21: no static change, no bump needed.
- Rules 1-7, 10, 12-17 and 20: not touched by this diff.

Security: the change only adds response headers. It handles no new input and reads no request data. No concerns.

Fit: the middleware uses the same `app.middleware("http")(fn)` style as `host_guard` and sits next to it. It is small and has no dead code.

Quality issues (blocking): none.

### Nits (non-blocking)

1. `tests/test_cache_control.py:151-162` (`test_middleware_keys_on_content_type_and_sits_beside_host_guard`): it asserts on source text with `inspect.getsource`. That restates the code and breaks if the code is reformatted, for example if the registration is wrapped. The behaviour tests (static CSS, 404 and healthz untouched; every HTML route covered) already show the middleware keys on content type. Acceptable because AC 6 asks for it. A behavioural alternative: add a test-only HTML route at an arbitrary path and assert it gets `no-cache`.
2. `src/vramsherpa/main.py:1355` comment ("Registered first so it sits inside host_guard"): the claim is true, but no test pins it. Swapping the two lines keeps all 27 tests green, because the 400 is JSON either way. This is fine as is. Optionally soften the comment, or leave it as a statement of intent.
3. `src/vramsherpa/main.py:121-123` docstring: it says `/results` answers a full page or a fragment "depending on the htmx headers" (plural). At this commit `results` branches only on `HX-Request`. The `HX-History-Restore-Request` branch arrives with R-081/ADR-0008 in a later task. This is forward-looking, not wrong.
4. `tests/test_cache_control.py:116-119, 138-141`: two tests rebuild `create_app(Settings(...))` by hand instead of reusing the conftest `app` fixture and adding the route to it. A small duplication.
