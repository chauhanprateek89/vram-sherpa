### Stage 2: code quality

- **Correctness:** the preload `href` and the `@font-face` URL are both built from the same origin (`url_for` gives an absolute URL, the stylesheet URL is absolute too), so the browser reuses the preloaded response; `crossorigin` matches the CORS mode fonts are always fetched in. The variable font covers weights 100-900, so the existing `font-weight: 500/600/700` rules render without faux bold. The legacy `--mono` alias drops IBM Plex Mono for a system monospace stack, which is the only option now that Google Fonts is gone.
- **Tests:** they test behaviour (the served HTML, the fetched font bytes, the parsed CSS blocks) and the brace-matching parser handles the nested `@media` block. Mutation runs confirm the dark-block, alias, font-URL and asset-version tests catch regressions. One gap is noted under nits.
- **Constitution:** rule 2 (Outfit is SIL OFL, free; licence shipped), rule 11 and 15 (removes a third-party request from first paint; htmx on unpkg stays, as ADR-0002 records), rule 18 (no check removed; the https asset URL check still covers the new preload because it uses `url_for`), rule 19 (no network, SQLite), rule 21 (static changed, version bumped). Rule 10 is QA's job later.
- **Security:** no new routes or inputs. The font binary is a verified byte copy of the approved design file.
- **Fit:** the CSS edits are mechanical and follow the file's existing style. The tests read like the rest of `tests/`.

No blocking issues.

### Nits

1. `tests/test_styles.py:82-96`: `test_stylesheet_starts_with_the_token_section` checks only a handful of token names, so a value drifting from `docs/design/tokens.css` goes unnoticed (in a scratch mutation, changing light `--bg` to `#FFFFFF` passed). Fixed would look like: compare the stylesheet from `@font-face` to the end of the saved-dark block with `tokens.css` from the same point, after swapping the `url()`.
2. `tests/test_styles.py:90,107`: the selector `':root,\n:root[data-theme="light"]'` depends on an exact newline, so reformatting the CSS breaks the tests without any behaviour change. Fixed would look like: match with a regex that allows `\s*` after the comma.
3. `tests/test_styles.py:140-145`: the stylesheet assertion sits inside the parametrized page test, so it runs three times, and it checks `fonts.googleapis.com` but not `fonts.gstatic.com`. The model detail page is also missing from the path list. Fixed would look like: a separate test that checks `styles.css` for both hosts, plus a `/models/...` path in the parametrize list.
4. `src/vramsherpa/static/css/styles.css:891,895`: two hard-coded colours (`#f9be2d`, `#e05050`) are still in legacy rules. These lines were already there before this task, and T-020 migrates them; noted here only so they aren't forgotten.
