### Stage 2: code quality

**Correctness.**
- `placeThumb` returns early when nothing is checked. `initSegThumbs` will not add a second thumb to a group that already has one (`has-thumb`). The listeners are registered once, from `DOMContentLoaded`.
- The form sits outside `#results-shell`, so an htmx swap never replaces the group, and the thumb survives with one instance (verified).
- `offsetLeft` and `offsetTop` are measured against `.seg`, which is `position: relative` and is also the thumb's containing block, so the coordinates match (verified at runtime).

**Old CSS removed safely.** The deleted rules (`.search-form`, `.hero-*`, `.input-path`, `.gpu-input-row`, `.context-buttons`, `.context-pill`, `.example-chips`, `.chip-example`, `.field-warning`, `.hero-actions`, and the old `.btn-primary`/`.btn-secondary`) have no other users in templates or JS. The only other `.btn-secondary` user is the `<noscript>` `Apply filters` button, and the new rule still styles it. The old `input, select, button` and `label` base rules are overridden by more specific `.form-pane` and `.seg` selectors, and the computed values confirm it.

**Tests.** The markup tests parse the HTML and check behaviour: ids, attributes, wording, one alert and one status, nothing inside the form. The CSS and JS tests match strings, so they restate code. With no JS test runner in the project that is acceptable, and the runtime checks above cover the gap.

**Constitution.**
- Rule 9 (Cache-Control): not affected.
- Rule 10: compared above, and QA still has to do its own pass.
- Rule 11: only GET; no new route or stored input.
- Rule 19: tests use SQLite and no network.
- Rule 21: bumped.
- Rules 1 to 8 and 12 to 20 are not affected.

**Security.** The template adds no new output of user input. `gpu_search_text` and `manual_vram_input` are still auto-escaped attribute values, as before. No new script source, request or dependency.

**Fit.** The new CSS block is copied from `components.css` in the one-line style the T-010 shell section already uses. It is headed with what it replaces and what still depends on old rules.

**Non-blocking quality issue (carry to T-021 and QA).**

- **Q-1: placeholder and value clipped at 390 px in Chromium.** `src/vramsherpa/templates/index.html:29` (`list="gpu-options"`). Chromium reserves room for the datalist picker indicator inside `#gpu_search`, so at 390 px the placeholder shows as `Start typing a GPU nam` and a selected GPU's label is cut off earlier than in the render. The mockup renders the field without `list`, and the copy table picked this placeholder because it fits in full at 390 px next to `Clear`. With `list` removed at runtime the placeholder shows in full; I confirmed this side by side. The task requires `list="gpu-options"`, so this is not a T-011 defect. It is fixed when T-021's combobox suppresses the native list while JavaScript runs (R-071 already requires that). If T-021 does not land, QA should decide whether to style `#gpu_search::-webkit-calendar-picker-indicator` for the no-JavaScript case.

### Nits

- N-1: `src/vramsherpa/templates/index.html:62`. The mockup puts `role="radiogroup" aria-label="Context window"` on `.seg`. The build leaves it out, and the `<fieldset>`/`<legend>` already groups and names the radios, so leaving it out is fine. Either add it to match the mockup or keep it out on purpose.
- N-2: `src/vramsherpa/static/js/app.js:209-210`. Under ADR-0008 a history miss reloads the full page, so the `htmx:historyRestore` listener does nothing. `load` and `pageshow` overlap as well. All of them are harmless.
- N-3: `src/vramsherpa/static/css/styles.css:935-937`. The thumb's own `prefers-reduced-motion` block duplicates the global `* { transition: none !important }` at line 873. It is harmless and makes the acceptance criterion explicit.
- N-4: `tests/test_ui_markup.py`. `test_app_js_places_a_thumb_and_replaces_it_on_every_layout_change` greps for strings, so it would still pass if the listeners were never registered. This is acceptable without a JS test runner.
