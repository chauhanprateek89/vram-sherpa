Checks made beyond the tests:

- **Mockup CSS.** `#results-feedback`, its 900 px rule, `.fb-spin`, `.fb-alert`, `.is-pending::after`, `.pager .is-pending` and `[aria-busy="true"] .card-grid` match the mockup's `<style>` block value for value. The mockup's `#results-feedback p` declarations are all on `.is-on`, as the task's notes direct. The mockup's `p { margin: 0 }` reset is absent from `styles.css`, and `margin: 0` on `#results-feedback p` makes up for it.
- **Containing block and stacking.** `.results-main` and `#results-shell` are `display: contents`, and `.bento` has no transform, filter or z-index, so the fixed element anchors to the viewport and `z-index: 60` sits above the sticky `.top` (20).
- **Lifecycle against the htmx 1.9.12 source.**
  - `onabort` and `onerror` fire `afterRequest` first, then `sendAbort` or `sendError`.
  - `responseError` fires inside the response handler, before `afterRequest`.
  - `htmx:abort` runs on the sync element, before the new `beforeRequest`.
  - A detached requester's `afterRequest` is fired again on the closest ancestor still in the document.
  - The test harness uses these same orders. The alert therefore survives its own `afterRequest`, and the new request keeps its loading state.
- **Scope.** The four other test files changed because they counted every `role="alert"` and `role="status"` on the page. Each still holds its messages to the same counts, and `_without_feedback` asserts that exactly one block was removed. The changes are necessary and weaken nothing.
- **`.sizes-seg .is-pending`** is not in the mockups, which draw no pending size. Without it, the spinner of a size link would anchor to a distant positioned ancestor, so it is a needed addition. QA has no mockup to compare this state with.
