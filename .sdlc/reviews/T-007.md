### Stage 2: code quality

- **Correctness:** the `|| true` on the `headers=` and `static_urls=` substitutions stops `-e`/`pipefail` from aborting before the explanatory error. With `pipefail`, a failing `curl -f` on `/` empties `static_urls`, and that goes to the "no /static/ URLs" failure, so the release still fails. The quoting is sound, and the `while read … <<<` loop handles URLs with query strings. Under GitHub's `-e`, a failing `printf | grep` inside `if !` does not abort the step.
- **Fit:** it uses the same idiom as the existing checks (`curl -s -o /dev/null -w '%{http_code}'`, `::error::` annotations, comments that say why each check exists and cite the ADR or rule).
- **Constitution:** rule 18 (added to, nothing weakened) and rule 20 (command unchanged) both hold. Rules 9, 19 and 21 are honoured as described above. No secrets or new permissions are added, and the step only makes requests to `127.0.0.1`.

No blocking quality issues.

### Nits

1. `.github/workflows/release.yml:170`: `status="$(curl -s … "$url")"` has no `|| true`. If an asset request times out or the connection drops, curl exits non-zero, and Actions' `bash -e` stops the step at the assignment. The `::error::Static asset …` line is never printed and the remaining URLs are never checked. The release still fails, so this is only lost diagnostics. Fix: append `|| true` (curl's `-w` already writes `000`), as `headers=` does.
2. Scope of what the check can see: it only fetches fonts that the HTML names, which under ADR-0002 is the preloaded primary face. Other `@font-face` files referenced by `url()` in `styles.css` are not fetched. This matches the acceptance wording, and T-006's package-data guard test covers the packaging side, so nothing needs to change now. Worth remembering if a font is added later without a preload.
