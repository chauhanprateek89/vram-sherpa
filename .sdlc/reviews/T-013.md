### Nits

- **N-1** `src/vramsherpa/static/css/styles.css:248`: the legacy `html, body { line-height: 1.45 }` predates T-013, and does not use the `--lh-body: 1.5` token that the mockups use. Each line in the tile is 0.75 px shorter than the mockup, and so is all body text elsewhere. Fixed would be `line-height: var(--lh-body)`, in whichever task owns the shell polish.
- **N-2** `tests/test_ui_markup.py`, `test_an_in_place_refresh_shows_only_the_current_querys_messages`: the last assertion (`"matched multiple" not in …vram_gb=24&gpu_search=`) can never fail, because that request never produces the message. A real check would request `gpu_search=RTX` with `HX-Request: true` first and assert the message is there, then repeat with `vram_gb=24` and assert it is gone.
- **N-3** `tests/test_ui_markup.py`, `test_answer_tile_css_matches_the_mockup_tokens`: this checks the stylesheet's text rather than behaviour, so it restates the CSS. It is cheap and guards against regressions, but the browser comparison above is what shows mockup fidelity.
- **N-4** `src/vramsherpa/templates/results_summary.html:16-43`: the alert and status `div`s are inserted together with the swapped shell, as before. Some screen readers do not announce a `role="status"` region that arrives already filled. This is the same behaviour as before T-013, and it matches the mockups. It is noted for an accessibility pass, not for T-013.
