### Stage 2: code quality

- **Correctness.** The click handler updates `aria-pressed` and `hidden` before any motion, so the switcher works when motion is off. `replayGauge` uses the same `htmx-added` double-rAF trick as the mockup. `addThumbs` is idempotent: it checks `has-thumb` and runs again on `htmx:afterSettle` and `htmx:historyRestore`. One delegated `pointermove` listener covers cards that are swapped in later. `prefersReducedMotion()` guards a missing `matchMedia`. The bar class re-derives `wont` in the template, and the verdict key is a dict lookup with no fallback (nit 2). Both are safe for the three classifications the estimator produces.
- **Security (rule 11).** No new route, parameter or stored input. Model names, the family and the quantisation labels are autoescaped. The inline `--i` style is an integer from `loop.index0`. The JavaScript writes only numbers into CSS custom properties. A template, CSS and JS change of this kind did not need a deeper security review.
- **Constitution.** Rule 16 holds: every pane shows the verdict, the margin, the required VRAM and the available VRAM. Rule 19 holds. Rule 21 holds. Rule 10 is covered by the comparison above, and QA still owes its own pass. Rules 9, 11, 12 and 17 are untouched.
- **Tests.** The markup tests check behaviour from the rendered HTML: element order, one gauge per pane, the bar class following the verdict, `data-oversize` matching `Won't fit` with the right title, and the gated tag inside the heading. They would fail on the old markup. The CSS and JS tests are string checks that restate the code (nit 3). There is no JavaScript test harness in the repo, so the browser run above is the real check of the switcher and the motion.
- **Fit.** The CSS is a line-for-line copy of `components.css` in the file's newer one-line style. The `app.js` changes follow the mockup's script and the existing `initSegThumbs` pattern.

### Nits

1. `src/vramsherpa/static/css/styles.css:807`: the comment says "the tag_gated macro", but the macro is `gated_tag`. Fixed: the comment names `gated_tag`.
2. `src/vramsherpa/templates/results_list.html:59` and `src/vramsherpa/templates/components.html:8`: the classification-to-key mapping exists twice. The template does `'wont' if … else classification_slug` and the macro has its own dict. The dict lookup also gives an empty modifier, not an error, for an unexpected value. Fixed: one source for the key, for example a `ResultRow.classification_key` property (or `classification_slug` returning `wont`) used by both the bar and the macro.
3. `tests/test_ui_markup.py:1041`, `:1064` and `:1079`: `test_verdict_and_margin_are_no_smaller_than_other_card_text` checks CSS strings, not rendered sizes. `test_app_js_motion_is_progressive_and_off_under_reduced_motion` greps for source text such as `pane.hidden = !show`. `test_asset_version_moved_on_for_the_card_restyle` pins `> "20261025h"`, which any later bump also satisfies. None of these would catch a behaviour regression that keeps the strings. Fixed: either accept them as guards, since the repo has no browser test harness, or move the size and motion checks into QA's browser script.
4. `src/vramsherpa/static/css/styles.css:770` (`.counts .num { font-family: inherit; }`) and `:868` (`font-family: inherit` on `.pick-meta`): these overrides are dead now that `.num` no longer sets the mono font. Fixed: drop both.
5. `src/vramsherpa/static/css/styles.css:845`: `.htmx-added .bar { width: 0 !important }` applies under reduced motion too. On an in-place refresh the bars show at 0 for one settle tick (about 20 ms) and then snap to width. This is not an animation and the mockup does the same, but wrapping the rule in `@media (prefers-reduced-motion: no-preference)` would avoid the blink.
6. `src/vramsherpa/static/css/styles.css:403`: `.results-cards` is a legacy rule that nothing uses, and it sits next to the new `.results` and `.card-grid`. It predates T-015. Fixed: remove it here or in the clean-up task.
