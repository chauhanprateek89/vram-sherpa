## Spec issues
- src/vramsherpa/static/css/styles.css:323-326 and :641, :663. Landing chips do not get the base chip look. In `docs/design/landing.css` the base look comes from `components.css` (`.btn-clear, .chip { min-height: var(--tap); padding: 0 16px; border-radius: pill; border: 1.5px solid var(--line); background: var(--seg); font-weight: 520; font-size: var(--fs-small) }`, plus hover/active). In `styles.css` the same rule is scoped `.btn-clear, .chips .chip`. The landing chips sit in `.launch-chips`, not `.chips`, so `a.chip` and `span.chip` there only get `display/text-decoration/color`: no 44 px min-height, no padding, no border, no pill radius, no background, no hover or press state. This breaks "chips at least 44 px tall" (R-070, Gate 2) and the match to the landing mockups. The inert chip is also wrong: `.chip[aria-disabled="true"]` sets `border-style: dashed` with no border width or colour, so it draws a default 3 px (medium) `currentColor` dashed border, not the 1.5px `--line` dashed look. Fixed: either widen the base rule to `.btn-clear, .chips .chip, .launch-chips .chip` (and the hover/active rules), or give the landing section its own `.launch-chips .chip` rule. Both must keep `a.btn-clear` the same look. T-031's `a#clear-gpu.btn-clear` is already covered by `.btn-clear`.
- The new pytest does not catch this. It only checks that the selectors exist in the file. Add an assertion that a rule matching `.launch-chips .chip` (or a widened `.chip`) sets `min-height` to `var(--tap)`, so the chip look cannot silently go missing again.
