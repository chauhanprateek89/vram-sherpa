### Nits (do not fail the review)

1. `tests/test_how_it_works.py:180-181` `test_estimation_module_untouched_by_this_task` asserts `main.estimate_breakdown is estimate_breakdown`. That is true for any edit to `estimation.py`, so the name claims a guarantee the test cannot give. Fixed looks like: delete it (the git diff is the real guard), or rename it to say what it checks (that the route uses the estimation module's function).
2. `src/vramsherpa/templates/how_it_works.html:53` The Required VRAM calc mixes rounded and unrounded addends: weights and overhead are printed with `%.2f`, while KV and the total are printed with `%g` of `round(5)`. With the seeded values it prints exactly the approved `4.95 + 0.98304 + 1.40 = 7.33304`. If the catalog ever gives a weights figure that needs more than 2 decimals, the printed sum will not add up. Fixed looks like: format weights and overhead in the calc strings the same way as KV (`'%g'|format(x|round(5))`), which still prints `4.95` and `1.4`. Note that the second gives `1.4`, not `1.40`, so the approved copy would need care. Low priority while the seeded values are what they are.
3. `src/vramsherpa/main.py:1345` The local `q4_variants` hard-codes "Q4" in its name while the filter uses `WORKED_EXAMPLE_QUANT_BUCKET`. Fixed looks like: name it `bucket_variants`.
4. `tests/test_how_it_works.py:142` The fallback test checks only `"Llama" not in html` for "no model name". It is adequate for today's catalog, but a check against every seeded model name would match the requirement's wording ("nor any other model name") more closely.
