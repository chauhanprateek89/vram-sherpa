### Non-blocking issues and nits

- `tests/test_brand.py:187-188`: `test_asset_version_is_new_for_this_task` pins `ASSET_VERSION == "20261025b"`. T-010 and every later task that changes `static/` will bump the version, so each of them must edit this test, and none lists `tests/test_brand.py` in its files. Fixed would mean asserting it is not `20261025a` or any earlier version (as `test_styles.py:121-122` does), or deleting the test, since `test_styles.py` already checks the format.
- AC 1 says "coloured by `currentColor` or tokens", but the approved mark uses fixed hex gradients, and `final-spec.html` says "Colours are fixed gradients that work on both themes, so the mark needs no theme switch". The builder correctly followed the approved mark. The task and ADR wording are out of step with the design, not the code. The architect could align ADR-0003 when convenient.
- `apple-touch-icon.png` is an opaque RGB image with white padding, so it is not a plain export of the transparent favicon. The commit message explains why: iOS fills transparency with black. That is reasonable, but QA should confirm the home-screen icon still looks right.
- Until T-010 adds the `.brand` flex rules, the inline 34 px SVG sits on the text baseline next to the wordmark. This is expected, because the task notes defer header sizing to T-010.
