## Nits
- src/vramsherpa/templates/index.html:17 with app.js:525: the plan note's claim that a stale `keyup` cannot follow the `submit` does not hold for key rollover. In htmx 1.9.12 the `changed` check compares with `lastValue`, which only a `keyup` updates. If Enter goes down before the last digit's key comes up, the digit's `keyup` arrives after the `submit`, passes `changed` and starts a new 350 ms delay. If the submit's response has not landed by then, the banner still holds the old verdict, so this request carries `verdict` and replaces the submit, and the user lands on the list instead of the gist (R-089). It needs a verdict list, a size field, rollover and a response slower than 350 ms, so it is narrow and is not a blocker. This comes from reading the source, not from a reproduction. Worth a QA probe with a throttled network. Fixed would be: clear the pending state on `submit`, or remember that a `submit` is in flight and add nothing until it settles.
