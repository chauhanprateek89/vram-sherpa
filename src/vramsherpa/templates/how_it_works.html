How VRAM Sherpa estimates fit (Policy {{ estimation_policy_version }})

VRAM Sherpa estimates whether a model variant can fit on your available VRAM for local inference. It is a planning estimate, not a benchmark.

Inputs

available_vram_gb

The VRAM you have, from the GPU you pick or the number you type.

From GPU selection or manual VRAM input

context_tokens

How much text the model keeps in view at once: 2048, 4096 or 8192 tokens, shown as 2k, 4k and 8k.

From presets (2048 default, 4096, 8192)

params_b

Model size in billions of parameters. A bigger model has more weights to store.

Variant and model metadata

bits_effective

Bits stored per parameter after quantisation: Q4 is 4.5, Q5 is 5.5, Q8 is 8.5, FP16 is 16. Fewer bits, less memory.

Variant and model metadata

kv_gb_per_1k_ctx

Memory the model's context (its KV cache) takes for every 1,000 tokens, in GB. Each model page shows this value.

Variant and model metadata

Formula

weights_gb

Memory for the model itself. Parameters times bits per parameter, divided by 8, gives gigabytes; the 1.10 adds 10% on top.

weights_gb = params_b * bits_effective / 8 * 1.10
kv_cache_gb

Memory for the context window you chose. It grows with the context length.

kv_cache_gb = kv_gb_per_1k_ctx * (context_tokens / 1000)
runtime_overhead_gb

Memory the runtime needs besides the model: a flat 1.0 GB plus 0.05 GB for every billion parameters.

runtime_overhead_gb = 1.0 + 0.05 * params_b
required_vram_gb

Everything the variant needs: weights, KV cache and runtime overhead added up.

required_vram_gb = weights_gb + kv_cache_gb + runtime_overhead_gb

Reserve buffer

reserve_gb

Free space to leave as a safety margin: 10% of your VRAM, never less than 0.75 GB.

reserve_gb = max(0.75, 0.10 * available_vram_gb)

With {{ rs.small_gb }} GB the reserve is {{ rs.small_reserve_gb }} GB. With {{ rs.large_gb }} GB it is {{ rs.large_reserve_gb }} GB.

Example with {{ rs.available_gb }} GB of VRAM

0{{ rs.fit_limit_gb }} GB{{ rs.available_gb }} GB

The reserve is {{ rs.reserve_gb }} GB. Up to {{ rs.fit_limit_gb }} GB Fits, up to {{ rs.available_gb_1dp }} GB is Tight, and anything more Won't fit.

Classification

{{ verdict("Fits") }}

It fits with the whole reserve to spare.

required_vram_gb <= available_vram_gb - reserve_gb
{{ verdict("Tight") }}

It can run, but it uses part of the reserve, so it is close to your VRAM limit.

available_vram_gb - reserve_gb < required_vram_gb <= available_vram_gb
{{ verdict("Won't fit") }}

It needs more VRAM than you have.

required_vram_gb > available_vram_gb

Limitations

Real outcomes vary by runtime, driver stack, memory fragmentation, and CPU/GPU offload behavior. This tool is not a benchmark and does not guarantee performance.
