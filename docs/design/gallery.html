Results gist

A search now lands on the answer, not on 71 cards. You see the headline, three controls (Fits, Tight, Won't fit) and Top Picks. Pressing a control shows that verdict's models, five or ten at a time. This is Gate 2: approve the screens, the notes on what did not work, and the open points at the bottom.

What did not work once drawn

  1. R-069's 900 px on the first card with verdict=fits did not fit at first. The first drawing measured 918 px. The heading row, the page sizes and the pick figures add about 160 px to the old 770. The list pane's top padding, the size control (44 px instead of 52) and the pick figures were tightened to reach 896 px. There are 4 px left, so anything added to the list's header or to Top Picks breaks R-069 again.
  2. A Won't fit card opens on a struck-through quantisation, and the approved style made it unreadable. components.css greys out a struck-through button, and the open button is filled. Together they gave about 1.2:1. Until now no card could open on a struck-through variant. The mockups keep the strike and use the pressed colour for the text of the open button (gist.css, last rule). The build needs the same rule.
  3. Top Picks can show a verdict whose count is 0. On the reference query Tight is 0, yet Best small is Yi-1.5 9B Chat at FP16, Tight, 0.5 GB spare. Counts place a model by the variant its card opens on (Q4 here, Fits); a pick can be any variant. Both are correct and both are on one screen. See open point 3.
  4. #results-list-shell is a grid item today, so an empty one still costs a row and a gap. styles.css puts it in row 3 across the whole grid. On a gist that leaves 14 px under the picks and an empty third row. The mockups make both shells display: contents and give the grid two rows, so the list pane is the only thing that can occupy row 3. Measured gap: 0 px.
  5. The form tile has slack on a gist. The right column is taller than the form, so the tile stretches. Filters (N) is pinned to its bottom edge, which leaves about 100 px of empty tile above it at 1280. It looks intended; the other option is to let the slack sit below Filters.
  6. The phone page controls wrap awkwardly. At 390 px the … that follows 7 starts the second row (… 15 Next). R-091 allows a wrap, and keeping Previous, the numbers and Next in one order for the keyboard rules out moving the two buttons to their own row. The alternative is a three-row stack, which is 50 px taller.
  7. R-084's note reads oddly when two controls are inert. /results?vram_gb=1 has Fits 0 and Tight 0, and the note under them says Choose Fits, Tight or Won't fit. The HLD table asks for the note whenever one count is above 0, so it is drawn. Dropping it when only Won't fit is above 0 would read better.

Open points

Each needs a yes or no from you.

  1. Back and Forward reload the page (HLD open point 1, ADR-0017). The design assumes yes: each Back or Forward within results is a full page load and a brief repaint, and no view is kept in localStorage.
  2. Loading and failure feedback on every results refresh, including refreshes that end on the gist (HLD open point 2, ADR-0018). Drawn: loading-from-gist and failed-from-gist show it. Saying no means the build checks the request's verdict first.
  3. Counts and Top Picks can disagree (item 3 above). Options: leave as drawn; or add the quantisation to a pick's verdict (Tight at FP16); or take picks only from each model's open variant, which changes R-024's rules and is a requirements change. I recommend leaving it as drawn.
  4. Where the feedback sits. Drawn at the top of the viewport (under the sticky header at 1280) because after Next the pager is at the bottom and a bottom message would cover the links. Say if you want it at the bottom.
  5. The failure message has no dismiss and no retry. R-090 asks for neither. The build must decide when it goes away; I suggest when the next request starts. It is not drawn with a close button.
  6. The selected-control cue. A 3 px ink border on the selected tile. If you prefer a filled tile, a corner mark or an underline, the measure to keep is 3:1 in both themes without relying on hue.
  7. The phone page controls (item 6 above). Natural wrap, as drawn, or the three-row stack.
